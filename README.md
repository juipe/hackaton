# Складчина

**Общие расходы — поровну и без споров**

«Складчина» — старое русское слово: сброситься всей компанией на общее дело.
Ровно это приложение и делает: ведёт общий счёт группы и отвечает на единственный
важный вопрос — **кто кому и сколько должен**.

Проект хакатона Сбера. Стек: FastAPI + PostgreSQL, React + TypeScript + Tailwind.

## Что это и зачем

Любая компания, которая живёт, ездит или работает вместе, упирается в один и тот же
разговор. Кто-то взял продукты, кто-то оплатил такси, кто-то внёс всю аренду за месяц —
и через неделю чат превращается в ленту разрозненных сообщений, по которой уже не
восстановить, кто кому должен. Дальше два пути: сесть с калькулятором и потратить
вечер или махнуть рукой и потерять деньги. Оба плохие.

«Складчина» ведёт этот счёт сама. Вы заносите расход — сумму, кто заплатил и на кого
делим, — а сервис считает доли, сводит все расходы и переводы группы в один баланс и
показывает, кто кому сколько должен. Запутанный клубок долгов упрощается до
минимального числа переводов, не меняя ничьего итога.

**Что умеет:**

- четыре способа деления: поровну, точными суммами, процентами, долями;
- балансы по группе и по каждому участнику, взаимозачёт внутри пары;
- упрощение долгов — «4 перевода вместо 7», балансы при этом не меняются;
- запись переводов между участниками (погашение);
- приглашения в группу по ссылке;
- аналитика: по категориям, по месяцам, баланс по участникам;
- лента событий по каждой группе и по всем сразу;
- всё на русском, все суммы в рублях.

## Запуск за одну команду

Нужен только Docker.

```bash
docker compose up --build
```

Откройте **<http://localhost:3000>** и войдите любым демо-аккаунтом.

Одна команда поднимает Postgres, ждёт его готовности, накатывает миграции, заполняет
демо-мир, запускает API на порту 8000, собирает фронтенд и отдаёт его через nginx на
порту 3000. `.env` создавать не нужно: у каждой переменной есть рабочее значение по
умолчанию.

Остановить и стереть базу вместе с томом:

```bash
docker compose down -v
```

**Полезные адреса после старта:**

| Что | Адрес |
|---|---|
| Приложение | <http://localhost:3000> |
| Swagger UI | <http://localhost:8000/api/docs> |
| ReDoc | <http://localhost:8000/api/redoc> |
| OpenAPI JSON | <http://localhost:8000/api/openapi.json> |
| Проверка живости | <http://localhost:8000/api/health> |
| Postgres с хоста | `localhost:5433`, БД/логин/пароль — `skladchina` |

## Что показать за пять минут

1. **Войти под Сашей** — он в трёх группах, на главной сразу виден итоговый баланс,
   разбивка «вам должны / вы должны» и график расходов по месяцам.
2. **Открыть «Квартиру на Вайнера»** → вкладка **«Балансы»**. Слева — кто кому должен
   с взаимозачётом внутри пары, справа — балансы участников. Переключатель
   **«Упростить»** сворачивает долги в меньшее число переводов; итог у каждого
   не меняется.
3. **Вкладка «Расходы»** — расходы сгруппированы по дням с подытогом за день,
   фильтры по категории, плательщику и периоду.
4. **«Добавить расход»** — ввести сумму (запятая работает: `4570,50`), переключить
   способ деления на **«Проценты»** и увидеть, как копейки сходятся в ноль в строке
   «Распределено».
5. **«Погасить долг»** — записать перевод и посмотреть, как пересчитался баланс.
6. **Войти под Жорой** и принять приглашение в «Хакатон Сбера».

## Локальная разработка

Нужны **Python 3.12+**, **Node 20+** (в Docker-образе — 22) и любая доступная
PostgreSQL. Бэкенд и фронтенд запускаются двумя терминалами.

### Бэкенд

```bash
cd backend
python -m venv .venv
```

Активация виртуального окружения:

```bash
# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Windows (Git Bash)
. .venv/Scripts/activate

# macOS / Linux
source .venv/bin/activate
```

Дальше одинаково:

```bash
pip install -r requirements-dev.txt
```

Укажите базу — например, поднятую этим же compose-файлом (`docker compose up db`):

```bash
# macOS / Linux
export DATABASE_URL="postgresql+psycopg://skladchina:skladchina@localhost:5433/skladchina"
export SECRET_KEY="любая-строка-не-короче-32-символов-для-разработки"

# Windows (PowerShell)
$env:DATABASE_URL = "postgresql+psycopg://skladchina:skladchina@localhost:5433/skladchina"
$env:SECRET_KEY = "любая-строка-не-короче-32-символов-для-разработки"
```

Либо положите их в `backend/.env` — файл читается автоматически и в git не попадает.

```bash
alembic upgrade head          # накатить схему
python -m scripts.seed        # залить демо-данные
uvicorn app.main:app --reload --port 8000
```

### Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Дев-сервер Vite поднимается на <http://localhost:5173> и проксирует `/api` на
`http://localhost:8000`. Браузер видит один источник, поэтому сессионная кука ведёт
себя ровно так же, как в продакшене — CORS и токены в заголовках не нужны.

Если API живёт не на 8000, задайте цель прокси:

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:8010 npm run dev
```

### Скрипты фронтенда

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер с HMR на 5173 |
| `npm run build` | проверка типов + продакшен-сборка в `dist/` |
| `npm run preview` | отдать собранный `dist/` локально |
| `npm run typecheck` | только TypeScript |
| `npm run test` | тесты Vitest один раз |
| `npm run test:watch` | тесты в watch-режиме |

## Переменные окружения

Файл-шаблон — `.env.example`; скопируйте при необходимости:

```bash
cp .env.example .env
```

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | `skladchina` | Доступы к базе в compose |
| `DATABASE_URL` | `postgresql+psycopg://skladchina:skladchina@db:5432/skladchina` | URL для API. В compose собирается из `POSTGRES_*`; задавать вручную нужно только при запуске без Docker |
| `SECRET_KEY` | значение для разработки | Ключ подписи сессионного JWT. **Вне разработки обязательно поменять** |
| `ENVIRONMENT` | `development` | `development` / `production` / `test` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080` (7 дней) | Срок жизни сессии |
| `COOKIE_SECURE` | `false` | `true`, когда сервис работает по HTTPS |
| `COOKIE_SAMESITE` | `lax` | Политика SameSite для куки |
| `COOKIE_NAME` / `CSRF_COOKIE_NAME` | `skladchina_session` / `skladchina_csrf` | Имена куки. Имя CSRF-куки продублировано во фронтенде (`src/lib/api.ts`) — менять только вместе |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:5173` | Список через запятую или JSON-массив |
| `FRONTEND_BASE_URL` | `http://localhost:3000` | База, из которой собираются ссылки-приглашения |
| `INVITE_EXPIRE_HOURS` | `336` (14 дней) | Срок жизни приглашения |
| `SEED_ON_START` | `true` | Заполнять демо-данные при старте контейнера (идемпотентно) |
| `FRONTEND_PORT` / `BACKEND_PORT` / `POSTGRES_PORT` | `3000` / `8000` / `5433` | Порты, публикуемые на хосте |

Сгенерировать свой секрет:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

> Порт Postgres на хосте — **5433**, а не 5432: локально установленный Postgres почти
> всегда занимает 5432.

## Миграции

```bash
cd backend
alembic upgrade head                                  # накатить
alembic downgrade base                                # откатить всё
alembic revision --autogenerate -m "что изменилось"   # новая ревизия
```

`alembic/env.py` берёт URL из настроек приложения, поэтому база выбирается переменной
`DATABASE_URL`. В Docker `entrypoint.sh` выполняет `alembic upgrade head` до старта API.

## Демо-данные

```bash
cd backend
python -m scripts.seed              # создать, если ещё нет (идемпотентно)
python -m scripts.seed --reset      # снести демо-мир и собрать заново
```

`--reset` удаляет демо-пользователей и все их группы вместе с расходами и переводами.
Ваши собственные аккаунты он не трогает.

Сид проверяет себя сам: суммы долей обязаны сходиться с суммой расхода, а сумма
балансов группы — быть нулём. Если данные в таблицах разъедутся, скрипт упадёт с
понятной ошибкой, а не создаст кривой мир.

│   │   ├── models/              # таблицы SQLAlchemy

│   │   ├── schemas/             # схемы pydantic (валидация и ответы)
│   │   ├── services/            # бизнес-логика

│   └── tests/                   # pytest
├── frontend/                    # React 18 + TypeScript + Vite + Tailwind
│   └── src/
│       ├── components/
│       │   ├── ui/              # примитивы (кнопка, поле, диалог, вкладки…)
│       │   ├── common/          # общие блоки (аватары, состояния, лента)
│       │   ├── layout/          # сайдбар, шапка, нижняя навигация
│       │   ├── balances/ expenses/ groups/ dashboard/ charts/
│       ├── hooks/               # обёртки TanStack Query над API
│       ├── lib/                 # api-клиент, деньги, форматирование, константы
│       ├── pages/               # страницы-маршруты
│       └── types/api.ts         # типы ответов API
├── docs/                        # контракты, по которым собиралось приложение
├── docker-compose.yml
├── .env.example
└── prompt.md                    # исходное задание хакатона

**Слои бэкенда.** Маршрут разбирает запрос и отдаёт ответ, сервис содержит правила,
репозиторий ходит в базу. Бизнес-логики в маршрутах нет — поэтому её можно тестировать
без HTTP.

**Данные фронтенда.** Ни одного ручного `useEffect(fetch)`: всё через TanStack Query
в `src/hooks`. Мутация инвалидирует затронутые ключи, и экраны обновляются сами.

## Дизайн-система

Интерфейс собран по макету из Claude Design в фирменной зелёной палитре Сбера.

- **Шрифт** — Golos Text (400/500/600/700/800).
- **Фирменный зелёный** — `#21A038`. Он работает на действиях: кнопки, активная
  навигация, активная вкладка, логотип.
- **Знак баланса** несут отдельные токены `--positive` (`#14732A`) и `--negative`
  (`#C62A1D`). Они темнее бренда, чтобы число читалось как число, а не как кнопка.
- **Форма** — всё кликабельное капсульное (`rounded-full`), карточки со скруглением
  28px и мягкой двойной тенью, фон приложения `#EEF2F0`.
- **Числа** — везде `tabular-nums`, чтобы суммы выстраивались в колонку.

Все значения — CSS-переменные в `frontend/src/index.css` и ключи в
`frontend/tailwind.config.js`. **Хардкодить цвета не нужно**: есть `bg-app`,
`text-dim`, `text-faint`, `bg-subtle`, `text-positive`, `text-negative`,
`rounded-card`, `shadow-card` и остальное из `docs/design-contract.md`.

> Осторожно: Tailwind молча не генерирует правило для класса, которого нет в конфиге —
> ошибки не будет, просто не применится стиль. Новый токен сначала добавьте в
> `tailwind.config.js`.

## Принятые решения

**Деньги — целые числа в копейках.** Ни одного `float` в расчётах. Деление на доли
раздаёт остаток по копейке (largest remainder), поэтому сумма долей всегда точно равна
сумме расхода: ни копейки не теряется и не появляется. Форматирование в рубли —
единственное место, где происходит деление, и только для показа.

**Четыре режима деления.** Поровну, точные суммы, проценты, доли. Все проверяются
на сервере: клиентский предпросмотр показывает то же самое, но авторитет — сервер.

**Упрощение долгов.** Жадный алгоритм сводит встречные переводы к минимуму:
результат — не более `n−1` переводов, и **ничей итоговый баланс не меняется**.

**Инвариант.** Сумма балансов любой группы равна нулю. Это проверяется в тестах и
в сиде — если инвариант нарушится, сборка упадёт.

**Аутентификация.** Сессионный JWT в HttpOnly-куке плюс отдельная читаемая
CSRF-кука, которую клиент возвращает заголовком на небезопасных методах. Токена в
localStorage нет, поэтому XSS не уносит сессию.

**Мягкое удаление расходов.** `deleted_at` вместо `DELETE`: история группы и лента
событий остаются целыми.

**Валюта одна — рубль.** Поле `currency` в схемах осталось для совместимости, но
сервер принимает только `RUB`.

## Работа в команде

**Ветки.** `main` держим рабочей: она должна собираться и проходить тесты в любой
момент. Всё остальное — ветками от неё:

```bash
git checkout -b feat/название-задачи
git checkout -b fix/что-чиним
```

**Коммиты** — по-русски, в повелительном наклонении, одно изменение на коммит:
`добавить фильтр по категории`, `починить перенос суммы на мобильном`.

**Что не коммитим:** `.env`, `.venv/`, `node_modules/`, `dist/`, `*.sqlite3`,
содержимое `__pycache__` — всё уже перечислено в `.gitignore`. Если файл с секретами
всё-таки понадобился, добавьте его в `.gitignore` до `git add`, а не после.

**Перед пушем** прогоните проверки из раздела [Тесты и линтеры](#тесты-и-линтеры).
Красных тестов в `main` быть не должно.

**Где что менять:**

| Задача | Куда идти |
|---|---|
| Новый эндпоинт | `backend/app/api/routes/` + `schemas/` + `services/` |
| Изменить правило расчёта | `backend/app/services/` (и тест рядом) |
| Изменить таблицу | `backend/app/models/` + новая ревизия Alembic |
| Новый экран | `frontend/src/pages/` + маршрут в `routes.tsx` |
| Новый запрос к API | `frontend/src/hooks/` + тип в `types/api.ts` |
| Поправить внешний вид | токены в `index.css` / `tailwind.config.js`, примитивы в `components/ui/` |
| Изменить текст | ищите строку в компоненте; тон и правила — в `docs/ru-contract.md` |

## Если что-то не запускается

**`docker compose up` падает на порте.** Значит, порт занят. Переопределите:

```bash
FRONTEND_PORT=3001 BACKEND_PORT=8001 POSTGRES_PORT=5434 docker compose up --build
```

**Порт 8000 занят чужим контейнером.** Частый случай — старый контейнер этого же
проекта. Посмотрите, кто держит порт, и остановите:

```bash
docker ps
docker compose down
```

**Фронтенд открылся, но всё пустое и «Требуется вход».** Дев-сервер проксирует `/api`
на `http://localhost:8000`. Проверьте, что бэкенд действительно там:

```bash
curl http://localhost:8000/api/health
```

Если API на другом порту — запускайте `VITE_API_PROXY_TARGET=... npm run dev`.

**Вход не проходит с верным паролем.** Имя CSRF-куки задаётся и на сервере
(`COOKIE_NAME` / `CSRF_COOKIE_NAME`), и на клиенте (`frontend/src/lib/api.ts`).
Если меняли — они должны совпадать.

**`ruff: command not found`.** Установите dev-зависимости:
`pip install -r backend/requirements-dev.txt`.

**Не хочется поднимать Postgres ради запуска.** Тесты идут на SQLite в памяти и базы
не требуют. А вот для реального сервера SQLite **не годится**: движок настроен на
одно общее соединение (`StaticPool`), и параллельные запросы к файловой SQLite падают
с `InterfaceError`. Для запуска приложения нужен Postgres.

**База «поехала» после экспериментов.** Полный сброс:

```bash
docker compose down -v
docker compose up --build
```
